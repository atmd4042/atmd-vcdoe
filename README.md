# اعتمد — المكتب الإلكتروني

واجهة عربية RTL لتطبيق خدمات «اعتمد». نقطة الدخول `index.html` تحوّل إلى `app.html`.

## الموجود في هذه النسخة

- مصادقة وحسابات وأدوار عميل/مقدم خدمة، باستخدام Supabase Auth.
- فهرس خدمات وأسعار وتصنيفات، وطلبات ومرفقات خاصة ومحادثات وإشعارات لحظية، باستخدام Supabase PostgreSQL وStorage وRealtime.
- تسليم ذري للطلب لمقدم خدمة معتمد، بحيث لا يمكن لمقدم ثانٍ استلام الطلب نفسه.
- لوحة إدارة لمراجعة مقدمي الخدمة وإدارة الخدمات والطلبات، محمية بسياسات قاعدة البيانات.
- زر واتساب في تفاصيل الطلب لبدء محادثة الدفع مع الرقم 0559384584.
- شاشة افتتاحية متحركة وهوية سوداء وذهبية، مع دعم المظهر الفاتح والداكن.
- لا يوجد تخزين بديل داخل `localStorage`: يلزم إعداد مشروع Supabase قبل تسجيل الدخول أو استخدام بيانات المنصة.

## إعداد Supabase (مطلوب للتشغيل الفعلي)

1. أنشئ مشروعًا في [Supabase](https://supabase.com/dashboard/projects)، وانتظر اكتمال تهيئة قاعدة البيانات.
2. افتح **SQL Editor** في لوحة المشروع، وانسخ كامل محتوى `supabase/schema.sql` وشغّله. يجهّز ذلك الجداول والسياسات والتخزين الخاص وفهرس الخدمات الأساسي.
3. من **Project Settings → API** انسخ **Project URL** ومفتاح **anon/public** فقط، وضعهما في `supabase-config.js`:

   ```js
   window.ETEMAD_SUPABASE_CONFIG = Object.freeze({
     url: 'https://YOUR_PROJECT.supabase.co',
     anonKey: 'YOUR_PUBLIC_ANON_KEY'
   });
   ```

   مفتاح anon/public معدّ للاستخدام في المتصفح؛ سياسات RLS هي التي تحمي البيانات. لا تضع `service_role` أو مفتاح `sb_secret_` أو كلمة مرور قاعدة البيانات في هذا الملف أو GitHub.

4. في **Authentication → URL Configuration** اضبط Site URL وعناوين إعادة التوجيه المسموحة، ومنها `http://localhost:8000/app.html` وعنوان التطبيق المنشور `https://atmd4042.github.io/atmd-vcdoe/app.html`.
5. اضبط مزود البريد الإلكتروني وقوالب التأكيد/استعادة كلمة المرور قبل استقبال عملاء حقيقيين. للتجربة الأولى يمكن تعطيل تأكيد البريد من إعدادات Auth؛ أعد تفعيله مع SMTP قبل الإطلاق العام.
6. أنشئ حساب المالك من شاشة التسجيل، ثم تحقّق من بريده، وبعد ذلك امنحه صلاحية المدير من SQL Editor باستخدام بريده الفعلي:

   ```sql
   update public.profiles
   set role = 'admin'
   where id = (
     select id from auth.users
     where email = 'OWNER_EMAIL'
   );
   ```

   لا تمنح دور المدير لأي حساب عام، ولا ترسل بيانات تسجيل دخول المالك لأحد.
7. شغّل محليًا بـ `python -m http.server 8000` وافتح <http://localhost:8000>. ستظهر شاشة إعداد واضحة إلى أن يكون عنوان المشروع والمفتاح الصحيحان موجودين ويعمل المخطط.

## التشغيل

شغّل خادمًا محليًا:

```powershell
python -m http.server 8000
```

ثم افتح <http://localhost:8000/app.html>.

## حدود الأمان والإنتاج

التطبيق يحتاج إعداد مشروع Supabase وتشغيل المخطط أعلاه قبل أن يعمل؛ ملفات المصدر وحدها لا تنشئ مشروعًا سحابيًا ولا تنشر قاعدة البيانات تلقائيًا. المرفقات خاصة ومقيدة بالمستخدمين المشاركين عبر RLS. لا ترفع كلمات مرور منصات حكومية أو بيانات بطاقة بنكية. اختبار طلب حقيقي يستلزم التحقق من سياسات RLS وإعداد البريد ونسخ احتياطية قبل استخدام مستندات حساسة.

تسجيل الدفع الإلكتروني غير مفعّل: زر واتساب يفتح رسالة لطلب بيانات التحويل البنكي ولا يخصم الأموال أو يؤكد استلام حوالة. إشعارات التطبيق تحفظ وتصل مباشرة عبر Realtime عند فتح التطبيق؛ لا يوجد إعداد FCM أو Push بالخلفية بعد. المواعيد ومراجعة الملفات الرسمية وعمليات حذف الحساب ليست مفعلة. أضف البريد والمعالجة القانونية وسياسة الخصوصية الفعلية ومراجعة أمنية قبل استقبال عملاء حقيقيين.

- <https://atmd4042.github.io/atmd-vcdoe/>
- <https://atmd4042.github.io/atmd-vcdoe/app.html>

اختر **Settings → Pages → Build and deployment → GitHub Actions** إذا لم يكن GitHub Pages مفعّلًا للمستودع.
